Login Page — Architecture Approaches

Vue 3 + Tailwind CSS · English · Full Vite project · 4 UI states

A

Single-component reactive (Recommended)

One LoginPage.vue — reactive ref() fields, computed CSS classes drive all 4 states (default, active, error, success). Inline validation on submit. No extra files.

Pros

  • Simple — holds in one file
  • Easy to understand & modify
  • No over-abstraction for a login page

Cons

  • Logic & template mixed if page grows
B

Composable-driven

useLoginForm.ts owns all state + validation logic. LoginPage.vue is purely presentational — binds to composable outputs.

Pros

  • Clean separation: logic vs. UI
  • Composable is unit-testable in isolation

Cons

  • Extra file for a single-page form
  • Slight overkill unless reusing logic
C

Component split (InputField + LoginPage)

Reusable InputField.vue component handles its own state display (error/success icons, border color). LoginPage.vue orchestrates. Matches how real design systems work.

Pros

  • InputField reusable across project
  • Clean prop interface: :error :valid

Cons

  • 2 component files instead of 1
  • More setup for a demo page
